请求参数

字段名变量名必填类型示例值描述

应答要求

收到异步通知后,请输出纯文本 success(不区分大小写,不要包含任何多余字符)表示接收成功。

未收到 success 应答时,系统将按 15s → 30s → 1m → 3m → 10m → 30m → 1h → 2h 的间隔自动重试,最多 8 次。通知结果可在商户中心「订单列表」中查看通知状态。

{{else if eq .DocPage "md5"}}

MD5 签名算法

1、将发送或接收到的所有参数按照参数名 ASCII 码从小到大排序(a-z),sign、sign_type 和空值不参与签名!

2、将排序后的参数拼接成 URL 键值对格式,例如 a=b&c=d&e=f,参数值不要进行 URL 编码。

3、再将拼接好的字符串与商户密钥 KEY 拼接后进行 MD5 加密,得出 sign 签名参数:sign = md5(a=b&c=d&e=f + KEY),结果为小写。

PHP 示例

<?php
function getSign($params, $key) {
    // 1. 过滤空值和签名参数
    $params = array_filter($params, function ($v, $k) {
        return $v !== '' && $v !== null && $k != 'sign' && $k != 'sign_type';
    }, ARRAY_FILTER_USE_BOTH);
    // 2. 按参数名 ASCII 升序排序
    ksort($params);
    // 3. 拼接键值对
    $str = '';
    foreach ($params as $k => $v) {
        $str .= "{$k}={$v}&";
    }
    $str = rtrim($str, '&');
    // 4. 拼接密钥后 MD5
    return md5($str . $key);
}

$params = [
    'pid'          => '1001',
    'type'         => 'alipay',
    'out_trade_no' => '20240101123456',
    'notify_url'   => 'http://www.example.com/notify.php',
    'return_url'   => 'http://www.example.com/return.php',
    'name'         => '测试商品',
    'money'        => '1.00',
];
$key  = '你的商户密钥';
$params['sign']      = getSign($params, $key);
$params['sign_type'] = 'MD5';

// 发起支付: 跳转方式
header('Location: https://pay.example.com/submit.php?' . http_build_query($params));

注意事项

· 参数值不要进行 URL 编码;· MD5 结果为小写;· 密钥请妥善保管,泄露后请立即在商户中心重置。

{{else if eq .DocPage "rsa"}}

RSA 签名对接

相比 MD5,RSA 签名下您的私钥无需随请求参与运算摘要,即使请求被截获也无法伪造新签名,安全性更高。已在商户中心上传 RSA 公钥的商户即可使用。

前置准备

1. 生成您自己的 RSA 2048 密钥对(openssl 示例):

openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out merchant_private.pem
openssl pkey -in merchant_private.pem -pubout -out merchant_public.pem

2. 登录商户中心 → 商户信息 → 粘贴 merchant_public.pem 内容保存;
3. 在同一页面复制平台公钥,用于验证平台发给您的异步通知签名。

请求签名

1. 与 MD5 相同:过滤空值与 sign/sign_type,参数名 ASCII 升序,拼为 a=b&c=d(值不做 URL 编码);
2. 用您的私钥对该排序串做 RSA-SHA256(PKCS1v15) 签名,Base64 编码后作为 sign;
3. 请求携带 sign_type=RSA。

openssl dgst -sha256 -sign merchant_private.pem -out sig.bin sorted_string.txt
sign=$(base64 -w 0 sig.bin)

验证平台通知

平台异步通知会带 sign_type=RSA 与 sign(平台私钥签名)。验证方式:按相同排序规则构造串,用平台公钥做 RSA-SHA256 验签:

openssl dgst -sha256 -verify platform_public.pem -signature sig.bin sorted_string.txt
# 输出 Verified OK 即签名有效
两种签名方式可共存:未携带 sign_type=RSA 的请求仍按 MD5 校验;清除商户公钥即整体回落 MD5。平台公钥可在商户中心-商户信息页随时复制。

监控部署详细教程

覆盖单账号、多账号轮询、云端挂机的完整部署方法与排障手册。先看原理,再照步骤做。

一、原理:钱到哪、谁通知、怎么匹配

买家下单 → 平台展示收款码(可多码轮询) → 买家扫码付款
       → 钱进入【收款码对应的账号】
       → 该账号所在手机收到官方到账通知
       → 手机上的监控 APP 提取金额,上报平台
       → 平台按「支付方式 + 金额(含随机尾数)」唯一匹配订单 → 订单完成

三条关键对应:

概念说明
收款码钱的入口,轮询 = 多个码按订单轮流展示
账号收款码背后实名的微信/支付宝/QQ 账号
监控手机挂着该账号、装了监控 APP、能收到到账通知的手机

一句话: 哪个账号的码在收款,就必须有一台挂着这个账号的手机在做监控。

二、准备工作

· 安卓手机或安卓云手机(安卓 8.0+,建议 12/14);
· 手机已登录收款用的微信/支付宝/QQ;
· 苹果手机无法做监控(系统限制),必须安卓或安卓云手机。

三、单账号部署(手把手)

第 1 步: 平台添加监控设备

管理后台 → 监控设备 → 添加设备 → 复制设备 Token(48 位)。

第 2 步: 安装监控 APP

手机浏览器打开平台 → 软件下载 → 下载 KunPayMonitor.apk 安装。

第 3 步: 配置 APP

填入平台地址(如 https://pay.example.com)与设备 Token,点「保存并连接」,顶部变绿"设备在线"即成功(30 秒/次心跳)。

第 4 步: 三项必要授权(缺一不可)

授权作用
通知使用权监听收款通知(核心),APP 内按钮跳转系统设置开启
通知权限Android 13+ 必需,缺了系统停发通知事件
电池白名单防杀后台掉线

厂商杀后台额外设置:小米(自启动+无限制省电)、华为(手动管理全开)、OPPO/vivo(自启动+后台运行)。

第 5 步: 验证全链路

创建小额订单 → 手机真实支付 → 观察通知 → APP 日志"已上报" → 平台订单变已支付。

第 6 步: 绑定渠道(建议)

渠道管理 → 对应渠道 → 绑定该设备:绑定后只接受该设备上报,防多设备串单。

四、多账号轮询部署

一台手机 = 一个微信 + 一个支付宝 + 一个 QQ(三通道独立开关)。N 个账号两种形态:

形态一(标准): 每账号一台手机/云手机
  账号1 → 手机 A(Token A) ┐
  账号2 → 手机 B(Token B) ├→ 全部上报平台 → 按金额匹配
  账号3 → 手机 C(Token C) ┘

形态二(同账号多码): 一台手机监控该账号,天然覆盖所有码

开启轮询: 管理员在渠道管理添加多码开轮询(可设权重);商户在「我的通道」绑定多码开轮询。建议每个渠道绑定对应监控设备。
为什么不会串单: 平台为每笔订单追加随机尾数(¥10 → ¥10.37),同刻在途订单金额全站唯一,到账只可能匹配那一笔。

五、云端挂机(7×24)

购买安卓云手机(红手指/河马/多多云等)→ 按第三节部署 → 云手机 7×24 在线。
有 Linux 服务器也可以 自建云手机: 开源 redroid 方案(Android in Docker), 一台服务器跑 N 台安卓容器,每台装 KunPay Monitor 监控一个收款账号; 完整教程见 GitHub 仓库 deploy/redroid自建云手机教程.md(含 docker-compose 多实例编排 与一键初始化脚本)。

六、常见问题排查

症状原因与处理
APP 显示等待收款通知不动通知使用权未授予 / Android 13+ 通知权限未允许 / 通知无"收款"关键词
心跳在线但订单不匹配金额或支付方式不符 / 渠道绑定了其他设备 / 订单已过期
锁屏后掉线电池优化杀后台,设置厂商白名单
两台设备同时上报渠道绑定专属设备即可
同金额订单互相干扰保持"金额尾数偏移"开启
苹果手机不支持,用安卓或安卓云手机

排查万能三步: ① 平台设备列表看在线;② APP 实时日志看有没有"→ 上报";③ 平台「到账流水」看记录,未匹配可手动匹配。

七、安全提醒

设备 Token 等同上报钥匙,泄露立即重置;只监控你自己的收款账号;微信/支付宝官方对非正常收款有风控,请控制频率与场景,商用依法合规。

监控APP对接

本平台通过「监控设备」接收收款到账通知。管理员在后台「监控设备」中添加设备获得 Token 后,在监控APP中配置即可。

方式一:平台自有协议

心跳地址:GET /monitor/heart?token={设备Token}

推送地址:GET /monitor/push?token={设备Token}&type={alipay|wxpay}&money={金额}&content={通知内容}

方式二:V免签(vmq)兼容协议

兼容 V免签监控APP,直接填入本平台地址与设备 Token 即可:

心跳地址:GET /appHeart?t={时间戳}&sign={md5(t+Token)}

推送地址:GET /appPushV?t={时间戳}&sign={md5(t+Token)}&type={alipay|wxpay}&money={金额}&content={通知内容}

返回格式

{"code": 1, "msg": "心跳成功"}
{"code": 1, "msg": "已匹配订单 20261012142704303043"}
{"code": 2, "msg": "已记录,未匹配到订单"}
{"code": -1, "msg": "设备token无效"}

云端挂机

自动监听需一台安卓设备(推荐部署在云手机上实现 7×24 挂机);Windows/macOS 监控助手可注册为系统服务在云服务器做心跳保活。平台支持主备设备自动接管:渠道绑定主设备后,主设备离线超过 5 分钟,备份设备的上报自动接管匹配。完整方案见仓库 deploy/云端挂机部署指南.md。

匹配规则

· 优先从推送内容中识别平台订单号精确匹配;· 否则按「支付方式 + 到账金额」精确匹配最早的待支付订单;· 为避免同额冲突,整数金额下单时会自动追加随机小数尾数(可在系统设置关闭);· 订单超时(默认 5 分钟)后不再参与匹配。

收款码轮询

商户中心「我的通道」中,同一支付方式可绑定多个自己的收款码:绑定 ≥2 个并启用后即可开启轮询,订单将按"最久未使用优先"轮流使用各个收款码,实现多码分摊收款。停用/删除导致启用码不足 2 个时轮询自动关闭;未绑定自有码的通道回落平台收款码。

事件推送(Webhook)

在商户中心「个人设置」配置 事件推送地址(event_webhook) 后,订单生命周期变化会以 JSON POST 推送到该地址(HTTPS 公网地址,平台禁止推送目标为内网)。

支持的事件

order.paid     支付成功(含管理员补单)
order.expired  订单超时未支付
order.refunded 订单已退款

报文格式

{
  "event": "order.paid",
  "trade_no": "202610151234567890123456",
  "out_trade_no": "商户订单号",
  "type": "alipay",
  "name": "商品名称",
  "money": "10.00",
  "timestamp": 1728950400,
  "sign": "md5签名",
  "sign_type": "MD5"
}

不同事件携带的字段略有差异:order.paid 含 name/money;order.refunded 含 refund_amount;order.expired 仅基础字段。

验签方式

与接口签名一致:对报文中除 sign/sign_type 外的全部字段(空值剔除)按 ASCII 升序拼 a=b&c=d,末尾拼接商户密钥取 MD5,与报文中 sign 比对(小写)。PHP 示例:

unset($_POST['sign'], $_POST['sign_type']);
$pairs = [];
foreach ($_POST as $k => $v) { if ($v !== "") { $pairs[] = "$k=$v"; } }
sort($pairs);
$raw = implode("&", $pairs) . $key;
if (md5($raw) !== $_POST['sign']) { die("verify fail"); }

注意事项

· 推送为单次尝试(10 秒超时),请保证地址公网可达、快速响应;· 未投递成功不影响入账,请以 api.php 查询或异步通知为准做兜底;· 同一订单的重复事件请以 trade_no 幂等处理。
