## 1. 准备清单

| 项目 | 要求 | 说明 |
|---|---|---|
| 服务器 | 1核1G 起,Windows / Linux 均可 | 推荐境内外连通性好的 VPS;有 [坤面板 KunPanel](https://github.com/kungec/kunpanel) 时可一键部署 |
| 域名(可选) | 一个解析到服务器的域名 | 正式使用强烈建议配置 HTTPS;纯 IP + 端口也能跑通 |
| 安卓手机 | Android 8.0+,能正常登录微信/支付宝/QQ | 实体备用机或云手机均可;需能收到收款通知 |
| 收款码 | 微信 / 支付宝 / QQ 个人收款码图片 | 个人码直收,资金直达个人账户,平台不经手 |

## 2. 部署服务端

### 方式一(推荐):坤面板一键部署

[坤面板 KunPanel](https://github.com/kungec/kunpanel) 是同作者的服务器运维面板,
在其「应用商店」里选择坤支付一键安装,反向代理 / HTTPS 证书 / 备份计划任务开箱即用。

### 方式二:Linux 一键脚本

```bash
curl -fsSL https://raw.githubusercontent.com/kungec/kunpay/main/scripts/install.sh | bash
```

- 自动下载对应架构的二进制并注册 systemd 服务,默认监听 `8080` 端口
- 升级:重新执行同一命令(数据保留);卸载:命令末尾加 `uninstall`
- 指定版本:`KUNPAY_VERSION=v1.3.5` 放在命令最前面

### 方式三:Windows 手动部署

1. 到 [Releases](https://github.com/kungec/kunpay/releases) 下载 `kunpay_windows_amd64.zip` 解压
2. 双击 `kunpay.exe`(或命令行 `kunpay.exe -port 8080`)
3. 浏览器访问 `http://服务器IP:8080/`

### 常用参数(可选)

| 参数 | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| `-port` | `KUNPAY_PORT` | 8080 | HTTP 监听端口 |
| `-db` | `KUNPAY_DB` | 程序目录 kunpay.db | SQLite 数据库路径,**请定期备份** |
| `-data` | `KUNPAY_DATA` | 程序目录 data/ | 收款码等上传文件目录 |

> 数据全部落在本机(单文件 SQLite + data 目录),迁移 = 拷走这两个文件。

## 3. 首次登录与基础设置

1. 浏览器打开 `http://服务器IP:8080/admin`,默认账号 **admin / admin123**
2. **首次登录会强制修改密码**(密码须 ≥6 位含字母;纯数字需 ≥10 位),请立即设置强密码
3. 进入「系统设置」,按需调整:

| 设置项 | 说明 |
|---|---|
| 站点名称 | 显示在收银台、通知等处 |
| 全局费率 | 平台向商户收取的手续费比例,默认 1.0%(独享费率可在单个商户上覆盖) |
| 订单超时 | 收银台倒计时,默认 5 分钟,过期订单自动关闭 |
| 金额尾数 | 开启后每笔订单自动加随机尾数(如 10.37),用于同一金额并发订单区分,一般保持开启 |
| 开放注册 | 是否允许访客自助注册商户;关闭后由管理员在「用户管理」手动开通 |
| GitHub 加速代理 | 服务器访问 GitHub 受限时配置,用于在线更新 |

4. 进入「渠道管理」确认三个通道(支付宝/微信/QQ)均已启用、单笔限额符合你的收款码额度

## 4. 配置收款渠道(收款码)

坤支付支持两类收款码,**个人收款码是核心玩法**:

### 4.1 平台统一收款码(管理员配)

管理后台 →「渠道管理」→ 对应通道上传收款码。

- 同一类型可上传多张并开启**轮询**(需 ≥2 张启用码),订单轮流使用,分摊收款
- 可绑定专属监控设备 ID,防止多台设备抢单
- 适合"平台统一收款、再手动/自动分账"的玩法

### 4.2 商户各自收款码(推荐:个人直收)

商户登录商户中心 →「我的通道」→ 各通道上传**自己的个人收款码**。

- 买家扫码后**钱直接进你的个人账户**,平台不经手资金
- 同通道多码同样支持轮询;设置别名(如"支付宝-张三")与权重
- 每通道最多 20 张收款码

> 没有绑定个人码的通道会回落到平台码;建议至少把主力通道(微信/支付宝)绑上个人码。

## 5. 安装监控APP并配对

监控APP 是"个人码直收"的灵魂:它挂在手机上监听微信/支付宝/QQ 的收款通知,
自动提取金额上报平台,平台据此把订单标记为已支付。

### 5.1 生成配对码

管理后台 →「监控设备」→ 新增设备 → 点击该设备的「📱 扫码配对」,
页面会生成 `kunpay://pair?...` 二维码。

### 5.2 手机端安装与配对

1. 到 [Releases](https://github.com/kungec/kunpay/releases) 下载 `KunPayMonitor.apk` 安装
   (或直接用手机扫设备页右侧的 APK 下载码)
2. 打开APP → 点「扫一扫」→ 扫上面的配对二维码
3. APP 自动填入平台地址与设备 Token 并**自动连接平台**——无需手动输入任何内容

### 5.3 完成三项必要授权(缺一不可)

配对完成后,按「必要授权」卡的提示逐项完成,**三项全部就绪监控才会启动**:

| 步骤 | 操作 |
|---|---|
| ① 通知使用权 | 点按钮跳转系统设置,找到「KunPay 监控」并允许 |
| ② 允许通知 | Android 13+ 系统会自动弹窗,点允许(否则监听事件被系统停发) |
| ③ 电池白名单 | 点按钮直接弹系统确认框,点「允许」(防止后台被杀) |

> 三项授权有任意缺项时,APP 会用黄色提示条**点名缺哪项**;补齐后 5 秒内监控自动启动。

### 5.4 确认运行状态

顶部状态卡应显示:**「设备在线」+ 最近心跳 + 监听正常**。
管理后台「监控设备」页对应设备也应转为在线。

可点 APP 里的「测试上报」发一笔 ¥0.01 模拟到账,验证链路连通。

## 6. 测试一笔真实支付

1. 让商户账号登录商户中心 →「支付测试」(或直接访问 `http://你的域名/demo`)
2. 选择支付方式,提交一笔 1 元订单,进入收银台
3. 用手机**按收银台展示的金额**扫码支付——**金额必须完全一致(含尾数)**,
   否则系统无法自动对账
4. 支付成功后:
   - 手机收到收款通知 → APP 日志出现"上报成功,匹配到订单"
   - 收银台页面几秒内自动跳转到商户的 return_url
   - 商户的 notify_url 收到异步通知(POST form,含签名)

**一条链路的判定口诀:通知收到 → 金额对上 → 订单完成 → 回调送达。**
任何一环断了,按第 12 节 FAQ 排查。

## 7. 商户接入(对接你的网站)

### 7.1 获取商户密钥

商户登录商户中心 →「商户信息」:记录 **商户 ID (PID)** 与**商户密钥**(点"查看密钥")。
密钥泄露 = 别人能冒用你下单,请妥善保管。

### 7.2 对接协议(易支付全兼容)

现有易支付商户系统**零改造接入**,三个接口:

| 接口 | 用途 |
|---|---|
| `GET/POST /submit.php` | 页面跳转支付(跳到收银台) |
| `GET/POST /mapi.php` | API 下单(返回收银台链接/二维码) |
| `GET /api.php` | 订单查询 |

完整参数、签名算法(MD5 / RSA-SHA256)、异步通知格式见平台内置文档:`http://你的域名/doc`
(含 submit / mapi / notify / 签名方式 / 支付方式 / 查询接口等分页)。

### 7.3 异步通知与对账要点

- 平台会向 `notify_url` 重试推送直到收到 `success`(纯文本)为止
- 商户侧验签:按文档对全部非空字段(除 sign/sign_type)ASCII 升序拼接 + 密钥做 MD5
- 事件类通知(支付/过期/退款)走 Webhook,可在商户中心配置,同样带签名

## 8. 商户中心日常使用

| 功能 | 入口 | 说明 |
|---|---|---|
| 仪表盘 | 商户首页 | 今日订单/成交额/可结算余额/近 7 日趋势,实时到账提醒 |
| 订单列表 | 订单管理 | 按状态筛选,查看每笔订单的通知投递状态 |
| 每日对账 | 每日对账 | 按日汇总 + 明细,支持导出 CSV、发送到邮箱 |
| 结算提现 | 结算提现 | 申请提现 → 管理员审核打款(或驳回退回余额) |
| 资金明细 | 资金明细 | 每一笔余额变动的 before/after 流水,审计级可追溯 |
| 邀请返佣 | 邀请返佣 | 邀请新商户注册,平台从其手续费中按比例返佣 |
| 快捷收款 | 快捷收款 | 不接系统也能收款:生成一个固定金额/任意金额的收款链接+二维码 |
| 工单支持 | 工单支持 | 与平台管理员沟通 |

> **退款**:商户可对自己已完成的订单发起退款(平台扣回该笔入账);管理员侧同样可操作。

## 9. 管理后台日常运营

- **订单管理**:全局订单检索/导出;对异常订单可「手动匹配」到账流水或「修复」;
  已完成订单可退款(会扣回商户入账并自动追回邀请返佣)
- **到账流水**:监控APP 上报的每一条收款记录;未匹配到订单的流水可手工指认
- **结算审核**:商户提现申请在这里「打款/驳回」,驳回自动退回商户余额
- **渠道成功率**:按通道统计近 7 日成功率,定位"某通道收款异常"
- **数据大屏**:`/admin/screen` 实时成交滚动屏,适合挂在屏幕上盯盘
- **平台收入 / 操作日志 / 数据清理**:手续费收入统计、管理员操作审计、过期数据自动清理
- **用户管理**:开通/封禁商户、调整费率与限额、调整余额(带流水)、重置密码

## 10. 挂机稳定性最佳实践

监控APP 的保活体系(v1.3.5 起)已覆盖:断开自动重连、进程被杀看门狗拉活(≤5 分钟)、
划掉任务自动拉起、开机自启。要让这套体系发挥最大效力,请再做好三件事:

1. **三项授权务必给齐**(①通知使用权 ②允许通知 ③电池白名单)——
   APP 会在缺项时点名提示,补齐自动启动
2. **国产 ROM 额外设置**:小米/OPPO/vivo/华为等系统请在系统设置中
   允许监控APP「自启动」「后台弹出界面」,并在最近任务里锁定它(下拉加锁)
3. **云手机 7×24 挂机**:不想用实体机可部署云手机,详见
   [deploy/云端挂机部署指南.md](../deploy/云端挂机部署指南.md)
   (redroid 自建云手机 / 云服务器方案 / 主备设备自动接管)

**状态速查**:打开APP 看顶部状态卡——
「设备在线 · 监听正常」= 一切正常;「⚠ 监听已断开,重连中」= 稍等自动恢复,
持续出现则重新开关一次「通知使用权」。

## 11. 在线升级

- **服务端**:管理后台 →「系统设置」→「检查更新」→ 一键升级
  (自动下载 GitHub 最新 Release 二进制并替换,Linux 下自动重启服务;数据不动)
- **监控APP**:APP 内每 24 小时检查一次更新,发现新版弹窗提示,
  点击「下载更新」覆盖安装即可,**配置与授权自动保留**
- 手动升级:重复执行安装脚本,或替换二进制文件重启

## 12. 常见问题 FAQ

**Q1:支付成功了,收银台不跳转?**
按顺序检查:
1. 打开监控APP 顶部状态卡:是否「设备在线 · 监听正常」?
   显示「监听已断开」→ 重新开关一次「通知使用权」;
   显示缺授权 → 完成「必要授权」三项
2. 后台「到账流水」里有没有这笔钱?
   - 有但未匹配 → 检查支付金额是否与收银台展示金额完全一致(含尾数)
   - 完全没有 → 通知没进来:手机通知栏能看到微信/支付宝的收款通知吗?
     看不到就是系统没发通知(检查微信「收款助手」消息是否被折叠/免打扰);
     看得到但 APP 没日志 → 重新开关「通知使用权」,或升级APP到最新版
3. 实在等不及:后台「订单管理」找到该订单 → 用到账流水「手动匹配」,立即完成回调

**Q2:APP 挂机一段时间就没反应了?**
升级到 v1.3.3+(监听断开自动重连)与 v1.3.5+(看门狗/开机自启),
并确认已加入电池优化白名单、国产 ROM 已允许自启动。v1.3.2 前的版本请务必升级。

**Q3:收到"微信收款助手 [N条]"的通知,金额识别错误?**
v1.3.2 已修复(旧版会把"[10条]"聚合计数当成金额)。请升级APP。

**Q4:提示"还差 ③电池白名单,监控不启动"?**
这是 v1.3.4 起的授权门禁:三项授权没给齐就不启动监控,避免"假在线真失聪"。
点「③ 电池白名单」按钮,系统弹框点「允许」即可,5 秒后自动开始监控。
电池白名单无法被 APP 静默自动授予,这是安卓安全模型的要求。

**Q5:同一时间多人扫同一个金额会串单吗?**
不会。开启「金额尾数」后,每笔订单的实付金额带随机尾数,按金额精确匹配;
同一秒的并发订单尾数互不相同。

**Q6:资金安全吗?平台会扣量吗?**
个人码直收,买家付的钱直接进你的个人账户;平台只记录订单与统计手续费,
不经手、不暂存货款。所有余额变动都有 before/after 流水,余额与流水强守恒。

**Q7:支持退款吗?退款后钱从哪扣?**
支持。退款金额从商户余额扣回(余额不足无法退款),同时自动追回该笔订单
产生的邀请返佣。商户中心和管理后台都可以发起。

**Q8:忘记管理员密码?**
按优先级尝试:
1. **其他管理员重置**:「用户管理」→ 对应用户 → 重置密码
2. **邮箱自助重置**:登录页点「忘记密码」,重置链接发到账号绑定邮箱
   (前提:账号已绑定邮箱,且系统设置里已配置 SMTP)
3. **服务器兜底**(仅唯一管理员且无邮箱时):停服务后用 bcrypt 新哈希直接改库,
   以重置为 `admin123` 为例:
   ```bash
   sqlite3 /你的路径/kunpay.db "UPDATE users SET password_hash=\
   '$(htpasswd -bnBC 10 '' 'admin123' | tr -d ':\n' | sed 's/^2y/2a/')' \
   WHERE username='admin';"
   ```
   重启后用 `admin / admin123` 登录并立即设置新密码。
   (需要 apache2-utils 的 htpasswd 工具;`2y→2a` 是 Go bcrypt 的前缀兼容写法)
