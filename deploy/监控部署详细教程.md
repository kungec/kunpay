# 监控部署详细教程(单账号 / 多账号轮询 / 云端挂机)

> 适用版本: KunPay v1.0.0+
> 配套阅读: [云端挂机部署指南](云端挂机部署指南.md) · 平台内文档 `/doc/monitor`

---

## 一、先搞懂原理(3 分钟)

整个"码支付自动到账"由四层组成,理解了对应关系,部署就不会乱:

```
买家下单 → 平台展示收款码(可多码轮询) → 买家扫码付款
       → 钱进入【收款码对应的账号】
       → 该账号所在手机收到官方到账通知
       → 手机上的监控 APP 提取金额,上报平台
       → 平台按「支付方式 + 金额(含随机尾数)」唯一匹配订单 → 订单完成
```

三条关键对应关系:

| 概念 | 说明 |
|---|---|
| **收款码** | 钱的入口。轮询 = 多个码按订单轮流展示 |
| **账号** | 收款码背后实名的微信/支付宝/QQ 账号,钱到它那里 |
| **监控手机** | 挂着该账号、安装了监控 APP、能收到该账号到账通知的手机 |
| **匹配** | 平台按金额匹配,与到账账号无关(尾数偏移保证同刻唯一) |

**一句话: 哪个账号的码在收款,就必须有一台挂着这个账号的手机在做监控。**

## 二、准备工作清单

| 项 | 要求 |
|---|---|
| 平台 | KunPay 已部署,后台可访问 |
| 监控手机 | 安卓 8.0+(建议安卓 12/14),能装微信/支付宝/QQ 并正常收钱 |
| 云手机(可选) | 红手指/河马/多多云等,用于 7×24 免真机 |
| 网络 | 手机能上网即可;云手机需能访问你的平台地址 |

> ⚠️ 苹果手机无法做监控(iOS 系统限制第三方读取通知),必须使用安卓手机或安卓云手机。

## 三、单账号部署(手把手)

### 第 1 步: 平台添加监控设备
1. 管理后台 → **监控设备** → 添加设备(名字随意,如"支付宝-小米手机")
2. 复制生成的 **设备 Token**(48 位,仅显示一次,注意保存)

### 第 2 步: 手机安装监控 APP
1. 手机浏览器打开平台 → **软件下载** → 下载 `KunPayMonitor.apk` 并安装
2. 安装时如提示"未知来源应用",允许即可

### 第 3 步: 配置 APP
1. 打开 APP,填入:
   - **平台地址**: `http(s)://你的平台域名`(例如 `https://pay.example.com`)
   - **设备 Token**: 粘贴第 1 步复制的 Token
2. 点 **保存并连接**,顶部变绿"设备在线"即成功(30 秒/次心跳自动保活)

### 第 4 步: 三项必要授权(缺一不可)
| 授权 | 作用 | 入口 |
|---|---|---|
| 通知使用权 | 监听收款通知(核心) | APP 内按钮跳转系统设置 → 找到 KunPay 监控 → 允许 |
| 通知权限 | Android 13+ 必需,缺了系统停发通知事件 | 系统弹窗点"允许",或系统设置 → 应用 → 通知 |
| 电池白名单 | 防止杀后台掉线 | APP 内按钮跳转,选"允许" |

**厂商杀后台额外设置**(否则锁屏几分钟就掉线):
- 小米: 自启动开 + 省电策略改"无限制" + 锁屏后不清后台
- 华为: 启动管理改"手动管理",三个开关全开
- OPPO/vivo: 允许自启动 + 后台运行权限 + 关闭"深度睡眠"

### 第 5 步: 验证全链路
1. 平台创建一笔小额订单(如 ¥0.01~1 元)
2. 用该手机上的微信/支付宝真实支付
3. 观察: 手机弹出官方到账通知 → APP 日志显示"已上报" → 平台订单几秒内变"已支付" ✓

### 第 6 步: 绑定渠道(可选但建议)
渠道管理 → 对应渠道 → 绑定这台监控设备。
绑定后**只接受该设备的上报**,防止你有多台设备时互相串单。

## 四、多账号轮询部署(N 个账号)

### 4.1 账号与设备的对应关系

**一台手机 = 一个微信 + 一个支付宝 + 一个 QQ**(三个账号组合,APP 内三通道独立开关)。

有 N 个收款账号时,两种部署形态:

```
形态一(标准): 每账号一台手机/云手机
  账号1(微信+支付宝+QQ) → 手机 A(设备 Token A) ┐
  账号2(微信+支付宝+QQ) → 手机 B(设备 Token B) ├→ 全部上报平台 → 按金额匹配订单
  账号3(...)            → 手机 C(设备 Token C) ┘

形态二(同账号多码): 一个账号生成多张码轮询
  只需一台手机监控这一个账号即可,天然覆盖所有码
```

### 4.2 部署步骤
1. 每个账号重复【第三节】,注意:
   - 每台手机用**自己的设备 Token**(不要复用)
   - 手机上登录**对应的账号**(微信/支付宝切换账号即切换监控对象)
2. 开启轮询:
   - **平台渠道轮询**(管理员): 渠道管理 → 添加多个收款码(每个码来自不同账号)→ 打开轮询 → 可设权重
   - **商户自有码轮询**(商户): 商户中心 → 我的通道 → 绑定多码 → 开启轮询
3. 建议: 每个渠道**绑定对应的监控设备**,只接受指定设备上报

### 4.3 为什么不会串单
- 平台给每笔待支付订单追加**随机尾数**(¥10 → ¥10.37),同一时刻在途订单金额全站唯一
- 到账 ¥10.37 → 只可能匹配到那一笔订单,无论钱进的是哪个账号
- 渠道绑定设备后,该渠道只认指定设备的上报,双保险

### 4.4 主备双保险
同一渠道可让多台设备都有覆盖: 主设备离线 5 分钟,系统自动切换由备份设备接管匹配,恢复后自动切回。

## 五、云端挂机(7×24 免真机)

真机方案的问题: 长期亮屏/保活麻烦。推荐用**安卓云手机**:

1. 购买云手机(红手指/河马/多多云等),选择离你买家近的机房
2. 云手机 = 一台云端安卓,重复【第三节】: 装 APP、登账号、授权、保活
3. 云手机 7×24 在线,平台侧看到设备常在线

监控APP 跑在收款手机或云手机上即可。
详细对比与脚本见 **[云端挂机部署指南](云端挂机部署指南.md)**。

**自建云手机**: 有 Linux 服务器的话,可以用开源的 **redroid**(Android in Docker)
自建整个云手机集群,零月租完全自主 —— 完整教程见 **[redroid自建云手机教程](redroid自建云手机教程.md)**,
配套 docker-compose 与一键初始化脚本在 [deploy/redroid/](redroid/)。

## 六、常见问题排查(按症状)

| 症状 | 原因与处理 |
|---|---|
| APP 显示"等待收款通知"不动 | ① 通知使用权未授予(设置→通知使用权);② Android 13+ 通知权限未允许(应用通知设置);③ 收款通知里没有"收款/到账"关键词 |
| 心跳在线但订单不匹配 | ① 到账金额与订单金额不符(尾数没输对);② 支付方式选错(微信到账配了支付宝订单);③ 订单已过期(超时作废);④ 渠道绑定了其他设备 |
| 手机锁屏后掉线 | 电池优化杀后台,按第三节第 4 步设置厂商白名单 |
| 两台设备同时上报同一笔 | 渠道未绑定设备,去渠道管理绑定专属设备 |
| 同金额订单互相干扰 | 开启"金额尾数偏移"(系统设置),保持开启 |
| 通知静默收不到(Android 13+) | APP 未获通知运行时权限,打开 APP 点"允许通知"重新授权 |
| 分身/双开的微信能监控吗 | 系统级通知可被监听,按文案识别上报;生产建议独立账号独立设备 |
| 苹果手机能做监控吗 | 不能,iOS 限制;用安卓手机或安卓云手机 |

**排查万能三步**:
1. 平台设备列表看是否**在线**(2 分钟内有心跳)
2. APP 实时日志看通知到达时有没有"→ 上报"记录
3. 平台「到账流水」看有没有这条到账,未匹配的会标红,可手动匹配

## 七、安全与合规提醒

- 设备 Token 等同于"上报钥匙",泄露后他人可伪造到账,**泄露立即在后台重置**
- 请监控**你自己的**收款账号;使用他人账号/协助第三方跑分属违法行为
- 微信/支付宝官方对非正常收款有风控,请控制频率与场景,商用请依法合规
