# 云端挂机部署指南

> 单账号/多账号配置细节与排障,见 [监控部署详细教程](监控部署详细教程.md)。

> 目标:让收款监控 7×24 小时在云端运行,不依赖家里的手机/电脑开机。
> 平台侧已内置**主备设备自动接管**:同一渠道绑定的主监控设备离线超过 5 分钟,
> 备份设备的上报会自动接管匹配,实现"云端 + 本地"双保险。

## 方案一:云手机挂机(推荐,真正的自动监听)

微信/支付宝/QQ 的收款通知只能由安卓系统捕获,因此**自动监控必须跑在一台安卓设备上**。
把监控 APP 装进"云手机",即实现云端挂机:

| 步骤 | 操作 |
|---|---|
| 1 | 购买云手机服务(红手指、河马云手机、VMOS Pro 虚拟机等均可) |
| 2 | 在云手机内安装收款微信/支付宝/QQ(用你的收款账号登录) |
| 3 | 上传 `KunPayMonitor.apk` 安装,或直接使用云手机应用市场中的 V免签类监控APP |
| 4 | 平台后台「监控设备」添加设备,复制 Token |
| 5 | 打开 KunPay 监控 APP:填入平台地址与 Token,授予通知使用权,关闭电池优化 |
| 6 | 平台后台设备列表显示"在线",完成 |

要点:
- 微信请开启「收款到账语音提示」,支付宝开启「收款到账提醒」,保证通知可达
- 云手机需保持微信/支付宝前台通知权限,建议开启APP自启动与后台保活
- 平台兼容 V免签协议,vmqApk 等现成开源监控APP同样可直接使用

## 方案二:云服务器挂机

Linux 云服务器直接运行一键安装脚本:

> 说明:桌面系统无法捕获手机收款通知,自动到账匹配仍需方案一的安卓端;
> 桌面助手的价值是 7×24 心跳保持设备在线、随时手动上报与联调,并可作为备用设备参与主备接管。

### Windows 云服务器

1. 上传 `KunPayMonitor_win64.exe` 到服务器(如 `C:\kunpay\`)
2. 右键管理员运行 `install-monitor-service.bat`(NSSM 一键注册系统服务)
3. 服务开机自启、崩溃自动重启;控制台 `http://127.0.0.1:8210`(本机访问,远程可用端口转发)

### macOS 机器

```bash
sudo mkdir -p /usr/local/bin
sudo cp KunPayMonitor_mac /usr/local/bin/
sudo cp com.kunpay.monitor.plist /Library/LaunchDaemons/
sudo launchctl load /Library/LaunchDaemons/com.kunpay.monitor.plist
```

### Linux 服务器

```bash
sudo cp kunpay-monitor_linux64 /opt/kunpay/
sudo cp kunpay-monitor-linux.service /etc/systemd/system/kunpay-monitor.service
sudo systemctl daemon-reload && sudo systemctl enable --now kunpay-monitor
```

## 方案三:主备双保险(推荐生产使用)

1. **主设备**:云手机跑安卓监控APP,渠道「绑定监控设备ID」填它的设备ID
2. **备份设备**:本地旧手机装监控APP,或云服务器跑监控助手
3. 主设备离线超 5 分钟,平台的**主备接管**机制自动让备份设备上报生效;主设备恢复后自动切回

配置位置:管理后台 → 渠道管理 → 渠道卡片「绑定监控设备 ID」。
填 `0` 表示任意设备均可匹配(不启用主备策略)。

## 常见问题

- **设备显示离线?** 最后一次心跳超过 2 分钟即判定离线;检查云手机网络、APP 后台保活、电池优化白名单
- **收到通知但未匹配?** 到账金额必须与订单应付金额完全一致(含尾数);查看后台「到账流水」与订单详情「通知投递记录」
- **同一笔上报会重复核销两单吗?** 不会。平台内置推送去重:30 秒内同设备/同方式/同金额/同内容的重复推送只核销一单
